## 2. Détail de la correction numérique J1

### 2.1 Quel était le vrai défaut ?

Le checker accepte la forme JSON `{"value":1e400}`, qui est **syntaxiquement un nombre JSON valide**. La bibliothèque Python `json.loads` peut en faire le flottant `inf`, qui n'est **pas** un argument numérique fini.

**Correction d'une imprécision de l'ancien audit :** sur Pydantic 2.13.5, `FunctionCall.model_dump(mode="json")` transforme un flottant infini présent dans `parameters: dict[str, Any]` en `None`. L'ancienne implémentation pouvait donc sérialiser `null` (valide syntaxiquement mais **type de paramètre invalide**), plutôt que nécessairement la constante non standard `Infinity`. La garantie du sujet était compromise sur le **type/la valeur**, mais l'ancienne affirmation d'un fichier contenant toujours `Infinity` était trop catégorique.

### 2.2 Correctifs effectivement fusionnés dans `main`

Dans [`src/argument_generator.py`](../src/argument_generator.py) :
- Pour un paramètre `number`, la conversion `float(value)` capture `OverflowError` sur les entiers gigantesques.
- `math.isfinite(value)` refuse `inf`, `-inf` et `nan`.
- Quand un token produit un objet terminé mais invalide, `generate` n'accepte plus l'objet et **continue à explorer le tas de candidats** au même pas de génération. Il ne s'arrête plus sur la première terminaison finie syntaxiquement mais incorrecte métier.

Dans [`src/__main__.py`](../src/__main__.py) :
- L'export préserve d'abord les données numériques via `result.model_dump(mode="python")`.
- `json.dump(output, file, indent=4, allow_nan=False)` empêche la sortie de constantes `NaN` ou infinies. C'est un **garde-fou supplémentaire** ; la validation métier doit déjà les refuser.

Dans les tests :
- `tests/test_argument_generator.py` : trois nouveaux tests pour la poursuite après `1e400`, le rejet de `inf/-inf/nan` et les entiers trop grands pour `float`.
- `tests/test_input_validation.py` : nouveau test qui vérifie qu'une sérialisation `model_dump(mode="python")` avec `allow_nan=False` rejette un infini.

### 2.3 Ce qui a été réellement vérifié

Une reproduction numérique séparée du chemin de validation a été exécutée en Python/Pydantic : **10 vérifications ciblées réussies** sur `1e400`, `-1e400`, `nan`, `inf`, `-inf`, entier géant, nombres normaux et sérialisation stricte. De plus, la différence entre `model_dump(mode="json")` et `model_dump(mode="python")` a été observée directement en Pydantic 2.13.5.

**Limite impérative :** il ne s'agit pas de l'exécution du dépôt complet. Les quatre nouveaux tests GitHub et les 42 précédents restent à relancer ensemble, soit **46 tests attendus**. Aucune affirmation de `46/46` ni d'amélioration sur le modèle Qwen n'est faite ici.

## 4. Architecture relue sur la version actuelle

### 4.1 `src/model/parser.py` — entrées JSON

- Lecture UTF-8 ; exceptions pour fichiers absents, UTF-8 invalide, JSON malformé, permissions.
- `object_pairs_hook=JsonParser._unique_keys` détecte les clés répétées **avant** l'écrasement par le dictionnaire Python.
- Rejet des noms de fonctions dupliqués et de la liste de fonctions vide ; messages Pydantic réduits à un diagnostic utile, avec numéro de définition/prompt.
- **Réserve :** le message de clé répétée donne le nom, pas son emplacement exact ; amélioration d'ergonomie seulement. `json.load` conserve par défaut une permissivité pour `NaN`/`Infinity` en entrée, qui ne remplace pas une politique stricte de lecture de fichiers.

### 4.2 `src/model/models.py` — schémas

- `Type`, `Function`, `Prompt` et `FunctionCall` sont Pydantic ; `extra="forbid"` sur les définitions.
- Types d'arguments autorisés : `string`, `number`, `integer`, `boolean`. Les noms de paramètres vides sont refusés.
- `Type.type` reste `str` pour les retours : à contrôler contre les cas de correction, **pas un échec démontré**.
- `FunctionCall.parameters` n'effectue pas de validation dynamique à lui seul ; cette responsabilité est bien assurée en amont par `ArgumentGenerator`.

### 4.3 `src/model/context_builder.py` — contextes

- Un contexte pour sélectionner la fonction, un pour générer tous ses arguments en une passe.
- Les descriptions et paramètres sont communiqués au modèle. La validité du format ne garantit pas à elle seule la fidélité du texte repris ; voir D2.

### 4.4 `src/function_selector.py` — sélection

- Décodage contraint aux noms encodés des fonctions ; meilleur logit autorisé à chaque position.
- Rejet de liste vide et d'ID de token hors vocabulaire.
- **À tester** : noms à préfixe commun, noms Unicode, logits `NaN`, tokenisation du nom selon le contexte. Les deux tests du sélecteur couvrent seulement des erreurs, pas un cas positif complet de sélection.

### 4.5 `src/json_checker.py` — automate JSON

- États explicites pour l'objet, les chaînes, nombres et booléens ; gestion des échappements et de `\uXXXX` ; contrôle des noms/types et rejet des clés répétées.
- `status` a trois résultats : `0` complet, `-1` préfixe valable, `-2` invalide.
- Le lexer numérique accepte les exposants arbitrairement grands ; c'est approprié comme syntaxe, avec **la vérification de finitude à la fin** dans le générateur (J1).
- `is_key_prefix` peut reporter le rejet de préfixes impossibles après un antislash ; cela fait surtout perdre du temps, le nom complet étant contrôlé à la fermeture.
- `status` repart de zéro pour chaque candidat ; risque de coût significatif.

### 4.6 `src/argument_generator.py` — génération

- Une seule génération JSON pour tous les paramètres, recherche des tokens autorisés par logits, cache du vocabulaire par instance et `heapq`, validation finale des clés/types.
- **Changement J1** : un objet terminé avec valeur non finie est rejeté ; le candidat suivant est essayé. Les nombres normaux conservent la conversion `number` vers `float`.
- Les nombres dépassant la capacité des flottants lèvent un `ValueError` explicite ; pas de remplacement silencieux par `null`.
- **D1** : `"\ufffd" in text` peut interdire la continuation d'un caractère UTF-8 fragmenté ; à reproduire avec les vrais tokens Qwen.
- **P1** : toutes les valeurs de logits sont encore parcourues pour construire un tas à chaque token ; `model.decode` et `checker.status` peuvent être sollicités de nombreuses fois. Le bénéfice du cache n'est pas isolé par une mesure de performance.
- **Limite fixe** : maximum 256 tokens par objet. Une entrée longue peut terminer par erreur plutôt que par un JSON complet ; limitation à documenter.

### 4.7 `src/__main__.py` — CLI et sortie

- Imports du SDK couverts par `try`, diagnostic convivial d'une dépendance absente, messages par prompt, codes d'échec et couleurs conditionnées au TTY.
- L'écriture est maintenant protégée par `allow_nan=False` et les données sérialisées en mode Python.
- **Limites** : *fail fast* si un prompt échoue, résultat écrit seulement à la fin, absence d'écriture atomique ; une sortie précédente peut subsister si une exécution échoue. Gérer le mode debug pour préserver la trace complète des erreurs inattendues serait utile.
